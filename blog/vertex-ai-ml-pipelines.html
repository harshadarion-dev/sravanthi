Building Production ML Pipelines with Vertex AI: Lessons from Enterprise Scale

By Sravanthi Maha · Apr 20, 2026 · 15 min read

Moving a machine learning model from notebook to production is one of the hardest problems in data engineering. After implementing ML feature pipelines at Wells Fargo — processing 100M+ records daily for real-time anomaly detection — I've developed a battle-tested architecture using Vertex AI Pipelines, Feature Store, and Model Monitoring.

The Production ML Pipeline Architecture

A production ML pipeline has four distinct phases that must all be automated and observable:

  1. Feature Engineering — Extract, transform, and serve features consistently across training and serving
  2. Training Pipeline — Orchestrate distributed training with reproducible experiments
  3. Evaluation & Validation — Gate model promotion on performance thresholds
  4. Serving & Monitoring — Deploy with observability and drift detection

1. Vertex AI Feature Store — The Foundation

The biggest ML antipattern is feature inconsistency between training and serving (training-serving skew). Vertex AI Feature Store solves this with a centralized feature registry that serves identical features to both training jobs and online prediction endpoints.

from google.cloud import aiplatform

# Register feature group
feature_store = aiplatform.FeatureStore.create(
    feature_store_id="transactions_fs",
    online_store_fixed_node_count=3,
    project=PROJECT_ID,
    location=REGION
)

# Ingest features from BigQuery
entity_type.ingest_from_bq(
    feature_ids=["amount_30d_avg", "velocity_score", "risk_flag"],
    bq_source_uri=f"bq://{PROJECT_ID}.features.transaction_features",
    entity_id_field="user_id",
    feature_time_field="feature_timestamp"

2. Kubeflow Pipeline for Training Orchestration

Vertex AI Pipelines runs Kubeflow-compatible DAGs on managed infrastructure. Each pipeline step runs in an isolated container, ensuring reproducibility and enabling parallel step execution.

from kfp.v2 import dsl
from kfp.v2.dsl import component, pipeline

@component(base_image="gcr.io/deeplearning-platform-release/base-cpu")
def train_model(
    training_data: Input[Dataset],
    model_output: Output[Model],
    n_estimators: int = 100
):
    import joblib, pandas as pd
    from sklearn.ensemble import GradientBoostingClassifier
    df = pd.read_parquet(training_data.path)
    X, y = df.drop("label", axis=1), df["label"]
    model = GradientBoostingClassifier(n_estimators=n_estimators)
    model.fit(X, y)
    joblib.dump(model, model_output.path)

@pipeline(name="fraud-detection-pipeline")

    train_step = train_model(training_data=feature_step.outputs["dataset"])
    eval_step = evaluate_model(model=train_step.outputs["model_output"])

3. Model Monitoring — Catching Drift Before It Hurts

At Wells Fargo, we set up Vertex AI Model Monitoring with alerts on both prediction drift (output distribution shift) and feature skew (training vs serving feature distribution). This caught a critical data pipeline issue that would have degraded fraud detection accuracy by 23%.

  • Set skew_thresholds per feature based on historical variance
  • Monitor prediction drift with Jensen-Shannon divergence
  • Alert on p-value thresholds for statistical significance
  • Auto-retrain triggers based on drift magnitude

4. CI/CD for ML — Automating the Promotion Gate

Never manually promote a model to production. Use Cloud Build + Artifact Registry to automate:

  1. Trigger pipeline on code push to main branch
  2. Run training pipeline with holdout evaluation set
  3. Compare against champion model on business metrics (AUC, precision@k)
  4. Auto-deploy challenger if metrics exceed threshold by >2%
  5. Gradual traffic rollout with canary deployment (10% → 50% → 100%)

Key Metrics for Production ML

  • Feature freshness latency (target: <5 minutes for online features)
  • Model prediction P99 latency (target: <100ms for online serving)
  • Training-serving skew score per feature (alert threshold: 0.1)
  • Model AUC degradation week-over-week (alert: >0.5% drop)
